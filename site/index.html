Digital forensics · Linux and macOS

One command from a collected host to a timeline.

nixcavate is a fast, single-binary forensic artifact parser. Point it at a UAC, Velociraptor or Aftermath collection, a mounted volume or a disk image, and get per-artifact CSV, JSON or JSONL, a task manifest and a super timeline. No runtime, no root, no network.

Quick start

Build it with a stable Rust toolchain. The binary is target/release/nixcavate.

# Build
$ git clone https://github.com/w0h1v/nixcavate && cd nixcavate
$ cargo build --release

# Parse everything in a collection, an archive or a disk image
$ nixcavate auto-parse -f evidence.tar.gz -o out
$ nixcavate auto-parse -f disk.E01 -o out -t jsonl

# Build the timeline from that run, with Sigma detections merged in
$ nixcavate super-timeline -d out --sigma detected_events.json

# Look for persistence, mapped to ATT&CK
$ nixcavate persistence-hunter -f evidence.tar.gz -o findings.csv

# One parser on one file, and the list of everything it can parse
$ nixcavate parse wtmp -f /cases/web01/wtmp -t jsonl
$ nixcavate list
auto-parse

Finds each host in the evidence, runs every parser, and writes per-host results and manifest.json.

super-timeline

Merges the timeline events of a run, and imported ChopChopGo or Zircolite results, into one sorted file.

persistence-hunter

Runs 32 checks mapped to ATT&CK techniques, with a YAML allow and block profile.

How it works

A run is split into many small tasks, the largest go first, and every task writes its own output. Nothing on the hot path is shared or locked.

OpenA directory, archive or image is listed once. Nothing is extracted.
DiscoverEach host root is found by layout, with its name, OS and time zone.
PlanOne task per file, and per 64 MiB chunk of a large text log.
ParseA fixed thread pool. A parser failure costs one task, not the run.
MergeTimeline events were written during the parse; the timeline is a parallel merge.

Inputs

Extracted collections and mounted volumes. .tar, .tar.gz, .tar.zst, .tar.xz and .zip read in place. Raw and E01 disk images with GPT or MBR partitions holding ext2/3/4, XFS or APFS. A folder of collections becomes several hosts.

Output

Per-host folders by category. Every row carries host, artifact, source_path and a line or offset. The manifest lists every task with its status, duration, record count and warnings. Exit code 0, 1 or 2 tells a pipeline success, partial failure or a run that could not start.

Honest timestamps

Every time is UTC and labelled with its precision and how it was obtained: recorded, assumed_zone or inferred_year. A syslog line with no year and no zone says so in the output.

Coverage you can see

Each task records the first and last event it parsed and the input's last-written time. When a log is cut or skipped, the summary shows the span that was not read.

Built for hostile evidence

Evidence is attacker-controlled. Five adversarial reviews and 33 fuzz targets shaped these rules, and every proven finding has a regression test.

  • Paths stay inside the evidence. Entry names are matched and displayed, never used as paths on the analyst's machine.
  • Symlinks are not followed out. A link inside a host root resolves against that root only.
  • Sizes are budgeted. --max-expansion stops decompression bombs in logs and archives.
  • A parser failure costs one task. Panics are caught at the task boundary and recorded in the manifest.
  • Filesystem walks are bounded. Path length, depth and node counts are capped, and each directory is read once.
  • Secrets are not written out. Shadow hashes, Wi-Fi keys and password verifiers are reduced to their type.
  • SQLite never opens evidence in place. Databases are copied to scratch and queried read-only.
  • Parsers are clean-room. Written from published format documentation and test data.
